# Patient Monitor

A **Digital Health / Healthcare IT prototype** for monitoring patient vital signs through a web-based application.

The project currently simulates a wearable device that generates heart-rate data, exposes the data through a **FastAPI REST API**, and displays it through a **Next.js / React frontend**.

The application is being developed incrementally, with the long-term goal of exploring device data ingestion, persistence, healthcare interoperability and standards such as **HL7 and FHIR**.

> **Current status:** Initial prototype — local development and mock data.

---

## Overview

The project explores a simplified healthcare monitoring workflow:

```text
Mock Device
     ↓
FastAPI Backend
     ↓
REST API
     ↓
Next.js / React Frontend
     ↓
Patient / Doctor Dashboard
```

The current implementation focuses on establishing the basic communication between a simulated medical/wearable device, a backend API and a web interface.

## Architecture

### Backend

The backend is responsible for exposing the data generated by the simulated device through a REST API.

```text
┌─────────────────┐
│   Mock Device   │
│                 │
│    device.py    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│     FastAPI     │
│     main.py     │
│                 │
│   GET /vitals   │
└────────┬────────┘
         │
         │ REST API
         ▼
```

### Frontend

The frontend is built with Next.js and React.

```text
                 ┌──────────────────────┐
                 │      Next.js         │
                 │       React          │
                 └──────────┬───────────┘
                            │
              ┌─────────────┴─────────────┐
              │                           │
              ▼                           ▼
      Patient Dashboard          Doctor Dashboard
              │
              ▼
        Vital Cards
```

The frontend communicates with the FastAPI backend through the API service defined in:

```text
Frontend/src/services/api.ts
```

## Getting Started

### Prerequisites

Install:

* Python
* Node.js
* npm
* Git

---

## Running the Backend

Open a terminal in the `Backend` directory.

If a Python virtual environment is configured, activate it:

```bash
.\venv\Scripts\activate
```

Then start FastAPI:

```bash
uvicorn main:app --reload
```

The backend should be available at:

```text
http://localhost:8000
```

### API documentation

FastAPI provides interactive API documentation at:

```text
http://localhost:8000/docs
```

The current prototype exposes:

```text
GET /vitals
```

This endpoint can be tested directly through the FastAPI documentation interface.

---

## Running the Frontend

Open another terminal in the `Frontend` directory:

```bash
npm run dev
```

The Next.js application should be available at:

```text
http://localhost:3000
```

Open this address in a browser to access the application.

## Data Flow

The current prototype follows this sequence:

```text
1. Mock device generates vital-sign data
              ↓
2. FastAPI exposes the data through /vitals
              ↓
3. Frontend API service requests the data
              ↓
4. React stores the received data
              ↓
5. VitalCard displays the vital sign
              ↓
6. Frontend repeats the request every 2 seconds
```

The polling mechanism provides a simple simulation of continuous monitoring.

## API Service

Communication with the backend is separated into:

```text
src/services/api.ts
```

The frontend uses this service to request data from the FastAPI backend rather than placing API calls directly throughout the UI components.

This creates a clearer separation between:

```text
UI Components
      ↓
API Service
      ↓
FastAPI Backend
```

## Project Purpose

This is a personal learning and portfolio project focused on **Healthcare IT and Digital Health**.

The purpose is to progressively understand how healthcare/device data can move through a software architecture:

```text
Device
  ↓
Data ingestion
  ↓
Backend API
  ↓
Data storage
  ↓
Healthcare interoperability
  ↓
Clinical application
  ↓
User interface
```

The project is intended to explore the technical concepts behind this workflow through a practical implementation.
